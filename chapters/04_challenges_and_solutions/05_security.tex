\section{Security}

\subsection{Challenge 1: Architecture search poisoning}

NAS-in-FL gives participating clients influence over both model weights and architecture parameters, creating two targets for malicious updates \cite{privacy_preserving_fednas_for_edge_2025}. An attacker can poison local data or manipulate its optimisation procedure so that the aggregated updates pursue a backdoor objective and corrupt the architecture search \cite{privacy_preserving_fednas_for_edge_2025}. Weight sharing can spread compromised weights across every candidate that reuses them, distorting comparisons throughout the search space. In an experiment with one attacker among eight clients and a fourfold update-scaling factor, ENAS search became nearly ineffective and SPOS performance declined markedly \cite{privacy_preserving_fednas_for_edge_2025}. The attacker can therefore corrupt a structural decision that persists in the selected architecture.

\subsubsection{Solution 1.1: Using Differentiable Search to Suppress Poisoned Operations}

SLNAS represents every candidate operation as part of a differentiable mixture. Each client updates both the operation probabilities and their weights. When poisoning makes an operation's weights oppose or contribute little to the main-task optimisation, later architecture updates reduce that operation's contribution \cite{privacy_preserving_fednas_for_edge_2025}.

\subsubsection{Solution 1.2: Restricting the Search Space before Federated Search}

GenoSpace restricts the search space before clients participate in the search. It evaluates candidate modules on server-held data and selects a set that jointly balances accuracy, memory, and latency. The resulting constraint on model complexity reduces the tendency to overfit noise introduced by a backdoor trigger \cite{privacy_preserving_fednas_for_edge_2025}.

\subsection{Challenge 2: Leaking client data through shared architecture updates}

NAS-in-FL communicates data-dependent search signals in addition to model weights. Differentiable methods share architecture-variable gradients, while other methods transmit discrete architecture graphs, client-specific architecture choices, or scalar rewards \cite{dp-fnas_2020,multi-granular_fednas_2023,privacy_preserving_fednas_for_edge_2025,feathers_2023}. Withholding raw data does not prevent leakage because these signals are computed from local training or validation data \cite{dp-fnas_2020,feathers_2023}. An honest-but-curious server or participant may use them to infer properties such as a client's sample count or class proportions, attempt to reconstruct training examples, or identify the source of an update \cite{multi-granular_fednas_2023,privacy_preserving_fednas_for_edge_2025}. Architecture search thus exposes information about client data through additional channels that fixed-architecture FL does not require.

\subsubsection{Solution 2.1: Applying Differential Privacy to Search Signals}

Differential privacy protects data-dependent search messages before clients upload them. DP-FNAS and FEATHERS clip model and architecture gradients and add Gaussian noise, while FEATHERS also perturbs hyperparameter rewards \cite{dp-fnas_2020,feathers_2023}. In vertical NAS-in-FL, SS-VFNAS applies the same principle to intermediate activations and backward gradients \cite{self-supervised_vertical_fednas_2023}. Clipping bounds the influence of each sample, while the noise obscures its contribution to the shared signal.

\subsubsection{Solution 2.2: Securely Aggregating a Uniform Shared Search}

SLNAS keeps a uniform differentiable search representation during collaboration. It applies the same weighted aggregation rule to model weights and architecture parameters, allowing secure aggregation to conceal individual search updates. After the shared search, each client selects and adapts its architecture locally, so the server does not observe its personalised choice \cite{privacy_preserving_fednas_for_edge_2025}.

\subsubsection{Solution 2.3: Sharing Low-Dimensional Discrete Architecture Encodings}

MGFNAS encodes each locally searched architecture as a discrete graph and handles model-parameter training in a separate stage. Its NAPA function aggregates graph entries into probability distributions and samples the next global architecture from them. This low-dimensional search signal makes exact gradient-matching reconstruction underdetermined. In the paper's seven-layer example, 56 architecture-gradient values constrain 50,176 unknown input pixels \cite{multi-granular_fednas_2023}.
