\section{Security}

NAS-in-FL communicates search state in addition to model weights. Architecture variables, candidate descriptions, rewards and shared supernet weights create further signals that can be manipulated or inspected. Security mechanisms must therefore protect both model optimisation and the structural decisions that determine the deployed architecture.

\subsubsection{Challenge 4.1: Poisoning the Architecture Search}

Malicious clients can manipulate model weights and architecture-search signals through poisoned data or local optimisation. The attack can therefore pursue a backdoor objective while changing operation probabilities or candidate rankings. In weight-sharing search, compromised weights can also affect every candidate that reuses them. Experiments with one malicious client among eight found substantial degradation in two discrete weight-sharing strategies under fourfold-scaled updates, showing that poisoning can persist in the selected architecture~\cite{privacy_preserving_fednas_for_edge_2025}.

\noindent\textbf{Solution 4.1a: Use differentiable search to suppress poisoned operations.} In differentiable supernet-based search, each candidate operation remains part of a weighted mixture while clients update both its weights and selection probability. If poisoning makes an operation's weights oppose or contribute little to the main-task objective, subsequent architecture updates reduce that operation's contribution to the mixture~\cite{privacy_preserving_fednas_for_edge_2025}.

\noindent\textbf{Solution 4.1b: Restrict the search space before federated search.} The server can evaluate modules on server-held data and select a compact set that balances predictive performance, memory and latency before clients begin differentiable search. Constraining model complexity in this way reduced overfitting to noise introduced by backdoor triggers in the cited evaluation~\cite{privacy_preserving_fednas_for_edge_2025}.

\subsubsection{Challenge 4.2: Architecture-Search Artefacts Can Leak Client Data}

NAS-in-FL communicates data-dependent signals that fixed-architecture FL does not require. Differentiable strategies can expose architecture gradients, while other strategies may transmit discrete architecture graphs, personalised choices or scalar rewards~\cite{dp-fnas_2020,multi-granular_fednas_2023,privacy_preserving_fednas_for_edge_2025,feathers_2023}. An honest-but-curious server or participant may use these artefacts to infer properties such as local sample counts or class proportions, reconstruct examples or identify the source of an update~\cite{multi-granular_fednas_2023,privacy_preserving_fednas_for_edge_2025}.

\noindent\textbf{Solution 4.2a: Apply differential privacy to search signals.} Differentiable strategies can clip model and architecture gradients and add Gaussian noise before upload, while scalar hyperparameter rewards can be perturbed in the same way~\cite{dp-fnas_2020,feathers_2023}. In vertically partitioned search, clipping and noise can instead protect the intermediate activations and backward gradients exchanged between parties~\cite{self-supervised_vertical_fednas_2023}. The added noise can, however, impair model and search performance~\cite{privacy_preserving_fednas_for_edge_2025}.

\noindent\textbf{Solution 4.2b: Securely aggregate a uniform shared search.} When every client updates the same differentiable supernet, model weights and architecture variables have aligned shapes and can use the same weighted secure-aggregation protocol. Personal architecture selection and adaptation can then occur locally after the shared search, preventing the server from observing each client's deployed choice~\cite{privacy_preserving_fednas_for_edge_2025}. This requires a uniform search representation during collaboration.

\noindent\textbf{Solution 4.2c: Exchange discrete architecture encodings separately from model parameters.} Strategies that produce discrete architecture graphs can upload these encodings while handling model-parameter training in a separate stage. The server can estimate distributions over graph entries and sample the next global architecture without receiving the corresponding weights or continuous gradients~\cite{multi-granular_fednas_2023}. In a seven-layer example, 56 architecture-gradient values were insufficient to determine 50,176 input pixels, making exact gradient-matching reconstruction underdetermined~\cite{multi-granular_fednas_2023}. The encoding remains data-dependent, so differential privacy or encryption is needed when a formal privacy guarantee is required.
